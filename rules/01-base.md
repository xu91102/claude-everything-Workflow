# 基础交付政策

- 先读取与目标直接相关的代码、配置和现有测试；目标项目自身约定优先，不用通用模板覆盖项目事实。
- 只修改能追溯到用户需求、失败用例或验证目标的最小范围；无关问题只记录，不顺手重构。
- 将任务转成可检查的完成标准，实施前明确最小验证方式；新增抽象、配置或扩展点必须解决当前真实复杂度。
- 保留用户已有改动，无法区分任务改动与用户改动时停止并说明冲突。
- 流程选择、继续和停止条件的唯一来源是 `skills/using-superpowers/SKILL.md`；本规则不复制 grilling、Spec、ticket、TDD、review 或 verify 状态机。
- 完成回报必须说明已运行验证、未运行项和剩余风险。
