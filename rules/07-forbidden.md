# 禁止事项 (CRITICAL)

本文件只保留跨语言、跨项目都成立的安全与交付底线。语言风格、日志 API、类型严格度和格式偏好不属于全局禁止项，应由项目配置或 `rules/common/language-quality.md` 按需约束。

## 安全禁止

NEVER 出现以下情况：

| 禁止 | 原因 |
|------|------|
| 硬编码密钥、令牌或密码 | 安全风险，使用环境变量或密钥管理服务 |
| SQL 字符串拼接用户输入 | SQL 注入风险，使用参数化查询 |
| 未校验不可信外部输入 | 可能导致注入、越权或数据破坏 |
| 明文存储密码 | 使用经过验证的密码哈希算法 |
| 吞掉错误或伪造成功结果 | 破坏可观测性与交付可信度 |
| 未经确认执行高风险外部写操作 | 可能造成不可逆影响 |

## 提交禁止

NEVER 提交以下内容：

| 禁止 | 原因 |
|------|------|
| `node_modules` 等依赖目录 | 仓库臃肿 |
| `.env`、凭据或私密数据 | 安全风险 |
| 无明确来源的生成产物 | 应由构建或发布流程生成 |
| 临时调试文件和无关备份 | 污染仓库与审查范围 |
| 无提交信息的提交 | 难以追溯 |

## 违规处理

发现违规时 MUST：

1. 立即指出问题和证据位置。
2. 提供最小修复方案。
3. 解释风险及验证方式。
