# 代码规模约束 (CRITICAL)

## 硬性限制

| 约束项      | 限制           | 违反后果               |
| ----------- | -------------- | ---------------------- |
| 单代码文件行数 | **≤ 800 行**   | 必须拆分文件           |
| 单测试文件行数 | **≤ 1000 行**  | 必须拆分测试场景       |
| 单函数/方法 | **≤ 80 行**    | 必须提取子函数         |
| 函数参数    | **≤ 5 个**     | 必须封装为对象         |
| 嵌套层级    | **≤ 4 层**     | 必须提前返回或提取函数 |
| 单行长度    | **≤ 120 字符** | 必须换行               |

**超限处理**：代码文件过长→拆分 | 测试文件过长→拆分场景 | 函数过长→提取 | 参数过多→封装对象 | 嵌套过深→早返回

## 执行要求

- 编辑代码后必须触发轻量代码规模检查，只检查本次编辑的代码文件。
- `*.test.*`、`*.spec.*` 和 `__tests__/` 下的测试文件上限为 1000 行。
- 文档、设计稿、规则说明等非代码文件不受 800 行限制。
- 检查通过时保持静默；只有代码文件超过对应上限时输出短警告。
- 收到超限警告后，先拆分职责、提取模块或拆分测试场景，再继续实现。
