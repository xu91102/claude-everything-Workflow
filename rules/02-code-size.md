# 代码规模约束 (CRITICAL)

## 规模目标与硬性限制

| 约束项         | 限制           | 处理要求                         |
| -------------- | -------------- | -------------------------------- |
| 单代码文件行数 | **约 800 行**  | 可略超，明显超出时评估是否拆分   |
| 单测试文件行数 | **≤ 1000 行**  | 必须拆分测试场景                 |
| 单函数/方法    | **≤ 80 行**    | 必须提取子函数                   |
| 函数参数       | **≤ 5 个**     | 必须封装为对象                   |
| 嵌套层级       | **≤ 4 层**     | 必须提前返回或提取函数           |
| 单行长度       | **≤ 120 字符** | 必须换行                         |

**规模处理**：

- 单代码文件以 800 行左右为参考目标，不是严格上限；
  为保持职责完整性可以略超，明显超出或职责混杂时再拆分。
- 测试文件过长→拆分场景 | 函数过长→提取 | 参数过多→封装对象 | 嵌套过深→早返回

## 执行要求

- 编辑代码后必须触发轻量代码规模检查，只检查本次编辑的代码文件。
- `*.test.*`、`*.spec.*` 和 `__tests__/` 下的测试文件上限为 1000 行。
- 文档、设计稿、规则说明等非代码文件不受代码规模目标约束。
- 检查通过时保持静默；非测试代码文件超过 800 行参考值或测试文件超过 1000 行上限时，
  输出短警告。
- 收到代码文件规模提醒后先评估职责是否完整，明显超出或职责混杂时再拆分；
  测试文件超限时必须拆分测试场景。
