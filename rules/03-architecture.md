# 架构与兼容性政策

- 先识别目标项目已有的模块边界、领域词汇、依赖方向和测试 seam；没有证据时不套用固定分层或目录模板。
- 新抽象必须减少当前复杂度、重复或耦合，并保持调用方更简单；优先局部、可回退的改动。
- 保留公共接口和数据格式兼容性，除非用户明确批准破坏性变化和迁移方式。
- 自动化脚本必须兼容项目声明的平台。跨平台仓库优先使用 Node.js 等统一入口，并通过项目实际包管理器和命令验证。
- 深模块、接口与 seam 的设计方法按需读取 `skills/codebase-design/SKILL.md`；领域边界变化按需读取 `skills/domain-modeling/SKILL.md`。
