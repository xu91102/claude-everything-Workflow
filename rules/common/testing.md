# 测试与验证

## 完成声明的证据

- 声明完成、修复、通过或 ready 前，必须有本轮针对最终状态的验证证据。选择足以支持结论的最小检查，读取输出和退出码，并逐项对照用户要求；修复结论须有原问题复现或回归验证。
- 本轮已有证据且相关状态未变时直接复用；仅在新改动、失败或未消除的疑点出现后重跑。检查失败按 `skills/systematic-debugging/SKILL.md` 的分级入口处理，预期的 TDD RED 留在实现循环。
- 委派结果须由控制者检查差异和必要验证，不能仅凭子代理自报完成。
- 报告实际检查命令或人工步骤及结果，说明未运行项、原因和剩余风险；结论不得超出证据覆盖范围。

## 默认策略

- 先识别仓库已有的 lint、format、单测、类型、构建和 E2E 命令，不发明替代流程。
- 中间步骤运行覆盖当前改动面的最小验证；完成、跨模块、高风险、发布或 PR 前升级到完整相关质量门。
- 无法运行某项检查时，说明原因、替代证据和剩余风险；不得把未运行写成通过。
- monorepo 的 consumer 依赖内部构建产物时，先构建对应上游 package。

## 基线失败

- 目标问题导致的失败：确认命中原症状后作为有效复现，继续修复，不要求先全绿。
- 已证实无关的历史失败：记录命令、失败和工作区基线；不妨碍本次判断时继续，并比较是否新增回归，不把整套检查报告为通过。
- 环境或相关失败使结果无法判断：先处理环境或继续定位；无法解决时明确报告验证受阻、缺口和剩余风险，不宣称已验证。

## 验证分层

1. 仓库卫生：临时文件、调试残留、敏感配置和无关改动。
2. Lint / Format：风格、导入和静态问题。
3. 单元或组件测试：本次行为、边界和错误路径。
4. 类型与构建：跨模块接口和真实产物。
5. E2E：核心用户路径、认证、跨服务和发布冒烟。

覆盖率与最终质量门服从目标项目配置；关键路径合并前必须覆盖或明确缺口。不为低风险文档或纯配置整理
制造没有行为价值的测试；使用解析、配置校验或既有验证器。全量 build 成本高时先用更窄检查反馈。

## 行为变化

TDD 是可选择的默认方法：用户或目标项目明确要求时严格执行 `skills/test-driven-development/SKILL.md`；其他行为修改可选择 TDD 或有充分证据支持的替代方法，简述验证依据，不省略必要测试和回归验证。已有正确复现目标失败的测试可直接复用；无行为变化的重构依靠已有测试、特征测试和必要补充验证，不人为制造 RED。原型与探索按探索目标选择方法，正式交付仍需满足对应质量要求。

测试优先稳定、合适的接口，层级由需要证明的性质决定；数据库状态检查、契约测试和低层验证在适用时有效。不得删除有效测试、削弱断言或修改预期来掩盖错误。

复杂、高风险或行为变化按需读取 `rules/09-first-principles-adversarial-testing.md`，覆盖异常状态、重复执行、权限、路径、跨平台和外部依赖失败。

## 端到端测试

Playwright 的组织、等待、POM、CI 制品和 flake 处理以 `skills/e2e-testing/SKILL.md` 为准；探索工具不能替代可重复的 E2E。本地多 worktree 运行时隔离端口和环境变量，启动服务必须等待 Web/API ready。CI 失败时按 `skills/e2e-testing/SKILL.md` 保留失败制品。
