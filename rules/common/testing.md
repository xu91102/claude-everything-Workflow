# 测试与验证

## 证据与复用

声明完成、修复、通过或 ready 前，须有本轮对应最终状态的真实证据，并逐项对照原始用户需求。
记录命令/人工步骤、退出码、关键结果、未运行项与剩余风险；委派结果由控制者复核，不只接受自报完成。
同一结论只验证一次。代码、测试、配置、依赖、环境及验收范围等相关输入未变且证据覆盖最终状态时，
在实现、审查、完成和 pre-pr 间复用；仅新改动、失败或未消除风险触发受影响项重跑。
不能把失败、跳过、缺失报告或未运行写成通过；必要质量门未满足时明确 FAIL、BLOCKED 或 NOT RUN。

## 选择验证范围

优先复用项目已有入口；项目约定、明确用户要求和受影响依赖优先于以下默认值。

| 改动面 | 最小充分验证 |
| --- | --- |
| 无行为变化的文档、格式或配置整理 | 相关解析、链接、配置校验或既有验证器 |
| 局部行为修复 | 原问题回归和受影响模块的测试 |
| 跨模块行为 | 受影响调用方的回归及适用类型/构建检查 |
| 公共 API/契约变更、依赖或构建链升级、发布 | 完整测试与构建，另补受影响调用方和关键路径回归 |
| 鉴权、持久数据或明确真实流程合同 | 对应完整质量门、真实关键路径及必要 E2E |

完成、提交或 pre-pr 本身不扩大验证范围；配置了 Playwright 不代表每次改动都要跑 E2E。
lint/format 使用项目已有入口；不为无关检查补装依赖。依赖或环境未变时不重复 setup。

## 行为与边界

修复目标以独立预期验证；按改动影响核对调用方、未改契约和失败路径。
验证针对实际需求与风险，不能用测试总数替代覆盖证据。
已有失败回归直接复用；需要新增/修改行为断言或显式要求时用 `skills/test-driven-development/SKILL.md`，
不在此复制 TDD 状态机。普通失败确认原因后修复；根因不明/重复失败按 `skills/systematic-debugging/SKILL.md`。

## 真实流程与 E2E

项目验收合同要求真实流程时，复用既有功能入口、用例和完成信号，不自动创建验收基础设施。
E2E 按 `skills/e2e-testing/SKILL.md`：隔离端口和环境变量，等待 Web/API ready，失败保留制品；模拟或局部检查不冒充真实验收。
