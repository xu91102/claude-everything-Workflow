# 测试与验证

## 完成声明的证据

- 声明完成、修复、通过或 ready 前，必须有本轮针对最终状态的验证证据。选择足以支持结论的最小检查，读取输出和退出码，并逐项对照用户要求；修复结论须有原问题复现或回归验证。
- 本轮已有证据且相关状态未变时直接复用；仅在新改动、失败或未消除的疑点出现后重跑。检查失败按 `skills/systematic-debugging/SKILL.md` 的分级入口处理，预期的 TDD RED 留在实现循环。
- 委派结果须由控制者检查差异和必要验证，不能仅凭子代理自报完成。
- 报告实际检查命令或人工步骤及结果，说明未运行项、原因和剩余风险；结论不得超出证据覆盖范围。

## 默认策略

- 先识别仓库已有的 lint、format、单测、类型、构建和 E2E 命令，不发明替代流程。
- 项目验收合同要求真实流程时，按 `skills/feature-acceptance/SKILL.md` 复用项目验收入口和功能地图；普通验证不自动创建验收基础设施。
- 按「最小验证白名单」选定覆盖改动风险的验证集，完成前补齐适用质量门；跨模块、高风险、发布或 PR 按实际影响扩展。完成声明本身不触发无关检查。
- 无法运行某项检查时，说明原因、替代证据和剩余风险；不得把未运行写成通过。
- monorepo 的 consumer 依赖内部构建产物时，先构建对应上游 package。

## 最小验证白名单

按改动面选择默认检查，适用于本地完成及提交前，不叠加同类检查。目标项目验收合同、改动风险、受影响依赖和相关质量门
要求的构建、全量回归或 E2E 必须执行，本地交付同样适用：

| 改动面                   | 必跑                       | 默认不跑（质量门要求时除外） |
| ------------------------ | -------------------------- | ------------------- |
| 单个纯函数或工具函数     | 该文件对应的测试文件       | 全量套件、E2E、构建 |
| 单个模块内部实现         | 该模块的测试目录           | 其他模块、E2E       |
| 跨模块接口               | 受影响模块测试 + 类型/构建 | 无关模块、E2E       |
| 公共 API、依赖升级、发布 | 全量测试 + 构建            | —                   |

- 同一结论只验证一次；相关代码、配置、依赖和环境未变时复用已通过的检查。
- lint / format 仅在仓库已有对应入口且适用于本次改动时执行，且只在提交或完成声明前跑一次；工具或打包配置存在不等于必须运行，不为无关检查补装依赖。
- 依赖安装与环境创建每个任务最多一次；不为单次验证新建虚拟环境或容器。
- 验证命令超过 3 条时，先说明为什么单条目标测试不足以支持结论。

## 验证分层

1. 仓库卫生：临时文件、调试残留、敏感配置和无关改动。
2. Lint / Format：风格、导入和静态问题。
3. 单元或组件测试：本次行为、边界和错误路径。
4. 类型与构建：跨模块接口和真实产物。
5. E2E：核心用户路径、认证、跨服务和发布冒烟。

覆盖率与最终质量门服从目标项目配置；关键路径合并前必须覆盖或明确缺口。不为低风险文档或纯配置整理
制造没有行为价值的测试；使用解析、配置校验或既有验证器。全量 build 成本高时先用更窄检查反馈。

## 行为变化

回归测试通过后还须检查补丁引入的新依赖和限制：局部操作是否开始依赖全局计算，原有合法输入的结果、异常或成本是否改变。
对受影响的值域、精度及已支持类型选取边界用例，比较修复前后的行为；未改动的契约必须保留。大型随机检查不能替代这些针对性检查。

改动循环、搜索或舍入逻辑时，分别覆盖：已支持类型的值域上下限及新增中间运算、完整选择语义（如重复值的首个匹配）、终止条件和最坏工作量。
用独立简单实现对照可枚举样本；边界附近还须检查试探、越界中间计算是否引入异常。对极端规模/精度做有界成本检查，不假设修正次数或误差很小。
预期结果不能复用被改算法；已有测试未覆盖这些风险时补对应断言，可并入同一验证命令，不必扩大到无关套件。

微改有现成回归测试时，可直接复用并确认修复前失败、修复后通过。需要新增测试、用户明确要求 TDD，或其他
新功能、bug 修复、重构引起的行为变化和公共 API 变化，使用 `skills/test-driven-development/SKILL.md`；
本规则不复制 RED/GREEN/REFACTOR 步骤。

复杂、高风险或行为变化按需读取 `rules/09-first-principles-adversarial-testing.md`，覆盖异常状态、重复执行、权限、路径、跨平台和外部依赖失败。

## 端到端测试

Playwright 的组织、等待、POM、CI 制品和 flake 处理以 `skills/e2e-testing/SKILL.md` 为准；探索工具不能替代可重复的 E2E。本地多 worktree 运行时隔离端口和环境变量，启动服务必须等待 Web/API ready。CI 失败时按 `skills/e2e-testing/SKILL.md` 保留失败制品。
