# 性能优化

## 模型选择策略

| 模型   | 适用场景                           | 成本 |
| ------ | ---------------------------------- | ---- |
| Haiku  | 轻量代理、高频调用、Worker 代理    | 低   |
| Sonnet | 主要开发工作、多代理编排、复杂编码 | 中   |
| Opus   | 深度架构推理、复杂分析、研究任务   | 高   |

默认使用 Sonnet，仅在需要深度推理时切换 Opus。

### 上下文窗口管理

- MCP 工具描述消耗 Token：同时启用少于 10 个 MCP、活跃工具少于 80 个，并用 `disabledMcpServers` 禁用未使用的 MCP。

### 上下文压缩规则

研究、里程碑或调试完成并准备切换阶段、放弃方案，或只需当前结论、关键文件和下一步时压缩上下文。

实施跨多文件功能、依赖近期调试细节、尚未整理阶段结论或关键阅读发现、未确认最新约束和风险边界时不压缩。

压缩前记录目标、已完成和待办、关键文件/接口/决策、风险/阻塞/下一步及待验证假设；压缩后确认目标与下一步仍一致、必要精确上下文可重开，且没有丢失约束、路径、变量名或错误细节。

## 代理团队成本

Agent Teams 会产生多个独立上下文窗口；仅在多模块工作或并行审查有明确收益时使用，简单顺序任务使用子代理更省 Token。

## 上下文窗口低区域

避免在上下文窗口最后 20% 做大规模重构、跨多文件功能或复杂交互调试；单文件编辑、独立工具类、文档更新和简单 Bug 修复对低上下文更不敏感。
