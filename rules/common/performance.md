# 性能与上下文成本

- 默认尊重用户选择的模型与推理配置，子代理继承该选择；不因任务简单或成本优化擅自降档。只有用户明确启用成本优先策略，或授权经任务评测验证的替代配置时，才权衡能力与成本。
- 优先减少重复阅读、无效工具调用、重复验证和无必要的代理交接，不削弱推理能力或丢弃关键证据。
- MCP 与工具按任务相关性、选择歧义、实际上下文开销和运行效果启用；无宿主限制或评测依据时不设通用数量门槛。遵守实际宿主权限、上下文上限和用户预算。
- 研究、调试或里程碑完成并准备切换阶段时压缩；依赖近期细节、关键决策未整理或风险未确认时不压缩。
- 压缩保留目标、进度、关键文件/接口/决策、风险、阻塞、下一步和待验证假设、关键已否定假设及反证；压缩后确认这些信息仍可恢复。
- 多 Agent 的选择以 `rules/common/agent-orchestration.md` 为唯一来源；性能评估只计算额外上下文、工具和回传成本。
- 上下文接近上限时避免启动大规模重构或复杂交互调试，优先完成当前可独立验证的切片并交接。
