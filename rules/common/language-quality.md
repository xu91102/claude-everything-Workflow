# 语言与项目质量策略

本文件是按需策略，不是跨项目默认硬规则。只有项目技术栈、现有 lint 配置、CI 或用户明确要求触发时才读取。

## 加载原则

- 先读取项目已有配置，例如 ESLint、Biome、Ruff、Clippy、golangci-lint 或编译器选项。
- 项目配置是事实来源；不要用通用 Harness 覆盖项目已有约定。
- 只对本次修改文件运行相关检查，除非任务要求全仓治理。

## TypeScript / JavaScript

- 在启用严格类型的项目中避免无理由使用 `any`；边界数据优先使用 `unknown` 并收窄。
- `console.log` 是否允许由运行场景决定：CLI 正常输出、构建脚本和诊断工具可能合理；应用调试残留应使用项目日志设施或删除。
- 不用 `@ts-ignore` 隐藏可修复问题；确有第三方类型缺陷时，记录原因并选择最窄豁免。

## 其他语言

- `dynamic`、反射、宏和运行时类型能力是否合理由语言与项目架构决定，不设全局禁令。
- 注释、文案和 emoji 是否允许由产品风格、终端兼容性和项目规范决定。

## 验证

优先运行项目已有 lint、format、typecheck 和目标测试。没有项目规则时，只报告建议，不擅自引入新的全局风格门禁。
