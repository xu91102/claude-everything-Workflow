# 创建项目验收技能

为目标仓库生成 `verify-<project>`：让后续 agent 能启动真实产品、检查环境、执行用户操作、观察结果并清理现场。项目命令、选择器、账号前置条件和功能地图留在项目中。

本技能改编自 pstack 的项目验收流程，来源与许可见[使用指南](../../references/project-verification.md#来源与许可)。

## 何时使用

用户明确要求创建或完善项目验收技能、操作工具或功能地图时使用，接受自然语言请求。仅发现项目没有工具时可建议此能力，不能把普通开发或一次验收自动扩展成工具建设。

已有项目验收技能且请求仅为检查漂移时，使用 `maintain-verification-skill`。

## 1. 从仓库确认运行模型

先读目标项目指令、README、构建脚本和相关验收入口，只问无法从代码或环境确定的用户选择。

| 需要确认 | 记录的事实 |
| --- | --- |
| 用户入口 | Web、桌面、CLI/TUI、API 或库的公开入口；多入口项目说明本轮覆盖面 |
| 启动与就绪 | 实际命令、工作目录、版本、端口、配置、认证、测试数据及可观察的就绪信号 |
| 操作与观察 | 已有 Playwright/CDP、PTY、HTTP、公开 CLI、测试脚本，以及截图、输出、退出码、文件变化等证据 |
| 隔离与归属 | 本轮创建的进程、端口、数据目录、浏览器配置和资源；共享实例是否允许操作 |
| 宿主发现方式 | 现有项目技能目录、命名和注册约定；Claude Code/Codex 哪些宿主需要使用 |

先试实际启动与只读检查。缺少依赖、登录或启动失败时标为 `BLOCKED`，保留原因；不要修改产品代码、伪造成功页面或发明启动命令绕过。用户已授权修复的另按项目交付流程处理。

## 2. 复用工具，补最小缺口

优先沿用项目已有且能驱动真实入口的工具与命令。浏览器/Electron 通常使用项目已配置的浏览器或 CDP；交互式终端使用已有 PTY；服务通过公开 HTTP；库通过公开 API 的真实调用。

只有已有工具不能完成操作时，才在项目验收技能目录中补一个薄的 CLI 或 helper：

- 提供启动、`doctor`（只读健康检查）、操作、观察和清理的能力；复用的命令无需改名或包装。
- 使用项目已有语言与依赖；明确实际支持的平台和 shell，不把未跑过的平台写成已支持。
- `--help` 说明参数、环境、示例和副作用；适合机器读取的结果用结构化输出，失败必须返回非零退出码。
- 操作参数显式指向本轮实例和数据目录，优先稳定选择器、提示文本、公开路由或命令，避免依赖坐标。
- 破坏性操作提供预览或项目已有测试模式；观察文件、网络或远端状态确认它实际跳过的副作用，不能只相信 `dry-run` 名称。
- 仅使用已获授权的测试账号、隔离数据及操作，不把凭据写进技能、地图、日志或提交。
- 脚本的可执行方式和完整调用示例写入生成的技能；实际运行帮助、健康检查、操作、失败退出与清理。

不为生成技能安装新的外部服务、创建云资源或改写全局 agent 配置。需要外部能力且尚未授权时说明缺口。

## 3. 生成项目技能与功能地图

按[生成模板](references/templates.md)组织输出，将模板变量替换为查证过的路径和命令：

- 优先放入目标仓库已有技能目录。没有约定时，按实际宿主选 `.agents/skills/verify-<project>/` 或 `.claude/skills/verify-<project>/`；需要两个宿主时沿用项目共享或分发方式，并核对两边发现入口。
- 不覆盖既有个人内容；复用已有验收技能时增量完善。位置存在多个有效候选且无法从请求确定时，询问目标。
- `SKILL.md` 包含合法 frontmatter，以及 Launch、Doctor、Drive、Evidence、Cleanup、Helpers。
- 需要注册时只更新项目要求的索引或清单，不向每个会话默认注入完整技能或功能地图。
- `features/README.md` 索引功能、用户入口和功能文件。先从路由、菜单、命令和文档选实际存在的 3–5 项；不足时按真实数量，明确其余范围。
- 每个功能记录用户可见目标、所有已知入口、操作方式、可观察断言、前置条件、限制和本轮覆盖。后续只按目标加载对应文件。

功能地图描述预期行为，注明来源；本轮观察和执行状态另存运行记录。不能把未执行的功能标为已验证，也不能用源码推断替代真实结果。

## 4. 按生成结果执行一次真实流程

从生成的技能冷启动执行：启动 → Doctor → 一个已映射功能 → 采集证据 → 复核 → Cleanup。

- 界面从真实页面或应用入口操作；CLI 从公开命令进入；服务或库走公开接口。测试辅助数据只作前置条件，内部 setter、模拟页面和测试专用成功接口不能代替用户流程。
- 保存操作前基线、触发动作和结果，核对相关文件、数据或外部副作用。真实 CLI/API 的输出可作 `log` 证据，界面流程需真实界面证据。
- 使用 `feature-acceptance` 的 `PASS / FAIL / BLOCKED / NOT RUN` 协议与证据复核标准；本轮只证明所执行的功能，其他功能明确 `NOT RUN`。
- 在已忽略的证据目录记录运行时间、代码版本、命令、退出码、断言和实际产物位置；公开报告只保留脱敏内容。
- 失败后再次 Doctor；健康检查无法解释界面卡死时重置本轮状态或重启本轮实例，清理失败尝试留下的资源后再试。
- 仅清理本轮创建且归属可核对的进程、会话、端口或临时数据；不按进程名批量终止。共享实例保留，仅清理本轮拥有的残留。
- 清理不得删除证据。最终重新打开关键证据，并确认产物在声明的位置仍可读取。

修正技能或 helper 后重跑受影响流程。未执行或缺少前置条件时交付 `BLOCKED` 草稿，不宣称工具可用；产品断言失败为 `FAIL`，不能弱化断言来换取通过。

## 5. 交付

报告生成位置、适用宿主和平台、复用/新增的命令、已执行功能与证据、清理结果、未覆盖项和总体状态。提交或 PR 沿用用户已有授权与项目流程。

提示 `maintain-verification-skill` 可检查后续漂移；仅在用户要求时建议频率或安排自动运行。
