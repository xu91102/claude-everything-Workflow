# 项目验收输出模板

用于创建项目技能。尖括号均为编写时变量；生成的可用文件不得保留占位命令或未查证的选择器。不适用的章节说明原因；不能编造成功信号。

## 目录

~~~text
<project-skill-directory>/verify-<project>/
  SKILL.md
  features/
    README.md
    <feature>.md
  scripts/             # 仅已有工具存在缺口时添加
~~~

启动和驱动细节留在技能，功能文件只描述对应入口与断言，避免重复一套会漂移的启动说明。

## SKILL.md 的最小契约

~~~markdown
---
name: verify-<project>
description: "验证 <project> 的 <实际用户入口>；在验收 <实际功能范围> 时使用。"
---

# <project> 真实流程验收

适用工作目录、平台/shell、代码版本检查方式与授权边界。
功能入口索引：features/README.md；执行前只加载所需功能文件。
结果遵守 PASS / FAIL / BLOCKED / NOT RUN；证据需独立打开复核。

## Launch
实际构建/启动命令、必要依赖、隔离参数、认证/数据前置条件及就绪信号。
长驻服务保留本轮实例；短命令每次使用明确的隔离数据目录或会话。

## Doctor
只读命令、预期输出、失败退出码；确认实例归属、工作目录、构建与认证。
第一次操作前执行，失败后重检；健康但卡死时重置或重启本轮实例。

## Drive
实际调用入口与参数，稳定选择器或公开命令。
操作具有的副作用、允许的测试模式、非零失败结果和错误恢复。

## Evidence
忽略目录中的持久证据路径，代码版本、时间、入口、动作、断言与退出码。
界面捕获真实截图/视频；CLI/API 保存公开入口的实际输出与状态变化。
截图、视频或日志如何复核，如何脱敏，未覆盖项如何报告。

## Cleanup
本轮资源的归属记录与精确清理命令，共享实例的处理。
失败尝试也要清理；保留证据，清理后重新确认它仍可读取。

## Helpers
每个已有工具/新增脚本的帮助与真实调用示例；没有 helper 时明确说明。
~~~

## 功能地图

`features/README.md` 保持短索引。一个功能文件对应一个用户可识别的能力；已知入口和关键分支在功能文件中列出，不通过隐藏入口缩减覆盖范围。

~~~markdown
# 功能地图

本地图范围、源码/产品约定来源、未纳入范围。

| 功能 | 用户入口 | 文件 |
| --- | --- | --- |
| <用户目标> | <实际菜单/命令/路由> | <feature>.md |
~~~

功能文件模板：

~~~markdown
# <用户目标>

预期行为及其来源路径；相关实现入口。执行结果另存运行记录。

## 子功能与关键分支
能力、错误/空状态/权限分支，以及不在本轮范围的部分。

## 用户如何进入
实际页面、菜单、公开命令/接口；认证、角色、平台和数据前置条件。

## 如何操作和证明
步骤与真实工具调用；先前状态 → 动作 → 可观察结果。
关键断言及副作用；证据位置和复核方式遵循 SKILL.md。

## 限制与恢复
易错条件、共享状态、Doctor/重置条件与清理说明。
不可达需保留尝试的入口与缺失条件，不能计为通过。
~~~
