# 维护项目验收技能

让项目验收步骤随产品变化保持可执行。维护单位是功能：源码说明与真实运行均要覆盖，单纯改文字或工具自身退出成功不足以证明完成。

本技能改编自 pstack 的维护流程，来源与许可见[使用指南](../../references/project-verification.md#来源与许可)。

## 入口与修改范围

用户明确请求维护、审计或检查项目验收技能/地图时使用，接受自然语言请求。普通功能开发或一次验收不会自动触发全地图维护。

先读项目指令，按已登记入口或现有项目技能目录定位包含启动、驱动和功能地图的技能。多个目标且无法从请求确定时询问；没有目标时报告 `BLOCKED` 并指出 `create-verification-skill`，不凭空生成。

只编辑目标技能的 `SKILL.md`、`features/` 及其拥有的 helper。共享 harness、产品源码、认证配置或既有测试归其他范围；发现问题先报告，已有授权明确覆盖时按对应交付流程处理。不要为维护改变产品行为。

## 1. 核对索引与预期行为

- 对照功能索引和实际功能文件，修正遗漏、重复、死链及失效入口。
- 每个功能从相关源码、产品约定与最近改动确认实现入口、用户路径、前置条件、预期结果和可能漂移；记录可复核路径。
- 对未入地图的能力，须有实际用户入口与来源证据再补充，不生成全仓库清单。
- 区分约定的预期与本轮观察；需求意图不明确时报告不确定性，不能仅因实现改变就删除预期断言。

默认由当前 agent 顺序读取与执行。仅在用户或项目流程已授权并行时，可把相互独立的源码核对分派给只读 agent；共享应用的驱动与状态仍由一个协调者串行拥有。

## 2. 全功能真实运行

按目标技能的运行模型启动：长驻 UI/服务使用本轮实例串行操作，短命令按每次隔离会话执行。合并可复用的前置步骤，但每个功能至少实际执行一次，覆盖地图列出的用户入口及关键断言；未执行分支逐项说明。

即使源码看起来没有漂移，也必须进行真实运行：

1. 第一次驱动前 Doctor；每次新会话和失败后重新检查实例、版本、认证及资源归属。
2. 健康检查通过但界面卡死或状态不可信时，重置本轮状态或重启本轮实例，不能继续盲目操作。
3. 捕获操作前状态、触发和结果，验证相关副作用。用 `feature-acceptance` 的 `PASS / FAIL / BLOCKED / NOT RUN` 协议逐项记录并复核证据。
4. 不可达功能记为 `BLOCKED`：记录已尝试的实际入口及具体缺少的账号、权限、平台或数据，不能计为成功覆盖。遗漏前置条件本身也是地图漂移。
5. 失败迭代清理本轮残留；最终停止所有本轮创建的实例和会话，保留共享实例。清理前后均确认已采集证据仍在声明位置且可读取。

运行记录放在已忽略的证据目录，包含代码版本、时间、功能覆盖、断言、证据和资源归属，不提交机器现场或秘密。

## 3. 分类处理并重新证明

| 发现 | 处理 |
| --- | --- |
| 入口、说明或前置条件与已确认的产品约定不符 | 修正地图或技能，核对来源与实际操作 |
| 产品行为正确，但目标技能拥有的工具无法启动、操作或观察 | 修正 helper/命令，运行帮助、失败退出、实际流程和清理 |
| 产品真实行为违背已确认的预期 | 记录 `FAIL` 与复现证据，单独报告产品问题，不弱化地图断言 |
| 缺少外部条件或预期意图不能确认 | 记录 `BLOCKED`、尝试路径和所缺条件 |

Doctor 因工具漂移失败时，在修改范围内修正并重试一次；按受影响内容重建或重启本轮实例。仍失败则报告阻塞，不反复猜测。

所有工具修正都要重新驱动受影响的真实功能；地图新增功能或改变操作路径时同样执行。最终清理在全部重新证明之后，并重新打开关键证据。

## 4. 报告与交付

报告逐功能的源码覆盖、真实运行状态、漂移修正、产品问题、证据复核与清理结果，并注明维护结果：

- `CLEAN`：功能与已声明入口完成源码和真实运行核对，无需修改；总体验收 `PASS`。
- `CHANGED`：存在已证明的地图/工具修正；分别报告修正验证和总体验收状态，产品 `FAIL` 不能被工具修正的 `PASS` 掩盖。
- `BLOCKED`：所需覆盖、重新证明或交付条件未完成；保留已通过/失败项，不宣称维护完成。

只有核心断言全部通过且证据已复核时，总体验收才能为 `PASS`。未执行分支写 `NOT RUN` 及影响；实际执行失败写 `FAIL`。

重新读每个修改文件并运行项目要求的验证。只有已有用户授权或明确项目流程要求提交 PR 时才提交一份聚焦的 PR；没有修改不创建空 PR，阻塞时先报告已证明与未完成的范围。不自动创建维护计划、通知或外部 Issue。
