# Triage

Origin: `mattpocock/skills@2ab9580`, adapted to this repository's confirmation boundary.

Read tracker operations and role mapping from `docs/agent-workflow/project-context.md`. If missing,
return `NEEDS_PROJECT_CONTEXT`.

## Roles

Category: `bug` or `enhancement`.

State: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`.

Every triaged item has exactly one category and one state. Conflicting states require maintainer input.
Apply configured label strings rather than assuming canonical names.

## Read-only Assessment

1. Read the complete issue/PR, comments, labels, author, dates and PR diff when applicable.
2. Read previous triage notes; do not re-ask resolved questions.
3. Inspect relevant code, domain vocabulary and ADRs.
4. Search for an existing implementation by domain concept.
5. Check `.out-of-scope/` for a prior rejected enhancement.
6. For bugs, reproduce the claim. For PRs, run the smallest check that verifies its claimed behavior.
7. Recommend category, state and next action with evidence. Wait for maintainer direction.

## Decision Work

Use `skills/grilling/SKILL.md` only when a consequential maintainer decision is missing. Use
`skills/domain-modeling/SKILL.md` when terminology or ADR-worthy decisions change.

## Mutations

Before commenting, labeling, closing or writing `.out-of-scope/`, show exact targets and actions and
obtain confirmation. Every generated tracker comment begins:

```text
> *This was generated by AI during triage.*
```

- `ready-for-agent`: use `references/agent-brief.md`.
- `ready-for-human`: use the same shape and state why agent execution is inappropriate.
- `needs-info`: record established facts and specific outstanding questions.
- rejected enhancement: follow `references/out-of-scope.md`.
- already implemented: point to the implementation; do not poison `.out-of-scope/`.

Return state changes, evidence, comments/brief references and remaining responsibility.
