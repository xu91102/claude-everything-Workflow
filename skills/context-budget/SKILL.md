# Context Budget

用这个 skill 找出“模型能力被上下文噪音吃掉”的来源。目标不是把能力砍少，而是让默认上下文只保留高频、通用、状态性强的内容，把其余能力改为按需 skill、CLI、脚本或浏览器原生能力。

## 工作流

1. 盘点常驻面：入口文件、规则索引、默认 MCP、agent 描述、自动加载 skill、hooks 配置。
2. 估算开销：Markdown 用 `words * 1.3` 粗估；代码和 JSON 用 `chars / 4` 粗估；MCP tool schema 按每个工具约 `500 tokens` 粗估。
3. 分类保留级别：
   - **默认保留**：几乎每个任务都要用，且按需加载成本更高。
   - **按需加载**：只在明确触发时读取，例如专项规则、技能说明、长参考。
   - **外移为 CLI/API**：无会话状态、一次请求即可完成，例如 GitHub、文档查询、包搜索。
   - **删除或合并**：与现有规则重复、描述太宽、没有明确触发或退出条件。
4. 输出整改建议：先列最大 Token 节省，再列误删风险和替代入口。

## MCP 默认策略

默认 MCP 必须同时满足两个条件：

- **通用**：几乎每个编码 agent、每个项目都会用。
- **MCP 明显优于 CLI/API/原生能力**：任务需要会话状态、交互式连接、流式上下文或结构化浏览；纯请求/响应工作不应作为默认 MCP 常驻。

不满足这两个条件时，优先改成：

- skill 调用本地 CLI，例如 `gh`、`git`、`npm`；
- skill 调用 REST/API，例如文档查询；
- harness 原生能力，例如内置 web search、memory、extended thinking；
- 可选 MCP 文档项，而不是默认启用项。

## 报告格式

```markdown
## Context Budget
- 估算常驻开销：
- 最大噪音来源：
- 建议默认保留：
- 建议按需加载：
- 建议外移为 CLI/API：
- 不建议修改：

## 优先整改
1. [路径/配置]：[动作] -> 预计节省 [tokens/原因]，风险：[低/中/高]
2. ...

## 验证
- [命令或人工检查]：
- 剩余风险：
```

## 注意事项

- 不要为了“省 Token”删除用户硬规则、安全边界或验证门。
- 不要把所有外部能力都降级成手写脚本；如果任务需要交互式浏览、调试会话或持久连接，MCP 仍可能是正确选择。
- 给出建议时必须说明替代入口，否则只是减配。
