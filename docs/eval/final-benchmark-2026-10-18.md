**2、2、2**。不能把自动完成率当作质量完全通过。

**AGENTS.md 与主分支逐字一致，净新增 0 行。** Fast Path 的入口位于已有 using-superpowers 技能，条件和护栏按需读取。

## 固定版本与方法

- 主分支：`e57aa53bb4b1ba8c065be5714c23e451bf6a6ad5`；最终规则：`f2f0d2773d001348b84a6d8a1457161b249f8117`。测量后只补结果文档，未再调整规则或判分器。
- Codex CLI：`codex-cli 0.160.1`；模型 `gpt-6.1-sol`、reasoning `high`；Node `v22.23.2`。
- 三臂使用同值配置与同一认证方式。裸跑没有安装 CEW；另两组从各自固定 Git 版本归档后安装到隔离 HOME。
- 42/42 次保留了相同的模型、推理强度和其他执行配置。CLI 只为各自 checkout 添加了 `projects.<checkout>.trust_level = "trusted"`，
  因而完整配置文件的首尾哈希不同；原始 `config_unchanged=false` 如实保留，执行字段未变的审计另见 `execution_config_unchanged` 和实验记录。
- 每次独立 checkout、HOME、Codex 状态和 Python venv；没有复用上一任务的对话或工作区。最多 2 个任务块并发，
  同题三组串行轮换，第二次重复反转顺序。位置数并非完全均衡，且服务端缓存与负载不能强制清空。
- 每次限制 720 秒；不补跑失败模型任务、不选择较优重复。源文件、任务清单的首尾哈希一致，配置哈希见实验记录。
- checkout 中移除了远程、tag、其他分支及不可达参考提交。所有组沿用同一个直接执行选项；共享源码仍位于文件系统，
  所以这是工作目录隔离，不能声称操作系统层面阻断了外部读取。是否读取参考答案另由完整命令轨迹审查。

任务预检：7/7 的原版目标测试实际执行后断言失败，参考修复目标测试和完整套件通过，收集错误均为 0。
SHA1 任务原来只导入修复后新增的私有函数，会导致原版无法收集测试；本轮在测量前将它替换为摘要行为断言，
并增加“删除 hashlib.sha1 后可导入、用 SHA256 签名并验签”的子进程测试。三组用同一修正，原版失败、参考修复通过。
这没有放宽对中断或收集错误的拒绝。补丁和完整预检结果见 [任务夹具](data/final-2026-10-18/task-fixtures.json)。

完成需同时满足：代理正常退出且未超时；基线完整套件、修复后目标与完整套件均实际执行完成；目标测试退出码 0 且
有实际通过用例；完整套件没有新增失败。修复后先恢复给定测试再独立判分，另行记录代理是否修改测试。
完整套件禁用提前停止，报告缺失、过期、损坏、全跳过、收集错误或执行中断均不算完成。

## 质量与限制

已完成全部 42 份补丁及命令轨迹的独立审查。36 份未发现重要质量问题；6 份 numeric_range 产物存在下述已披露的边界回退。
未发现测试配置规避、测试数量减少、新增跳过、越界读取参考答案或启动额外模型的证据。
42 次配置和依赖审计相符：配置仅增加 checkout 信任条目，5 次补装检查工具及依赖，没有替换既有测试依赖。

补充检查发现 numeric_range 的 index()/成员查询可能先求整个范围长度，将原有的总长度限制扩散到原本正常的查询。
输入 `numeric_range(0.0, 1e308, 1e-308)` 查询起点，以及 Decimal 精度 2 下范围 `(0, 10, 0.1)` 查询 0：
父版分别返回 True/0，有问题的产物则抛 OverflowError 或 InvalidOperation，导致查询失败。
还发现日期边界的另一类回退：`numeric_range(datetime.max - timedelta(days=1), datetime.max, timedelta(days=2))`
及下界镜像，原版的 len(r)=1、r[0] 可用，有问题的长度校正则因计算边界外的日期抛异常。
上游参考修复也存在这两类限制，
所以“与参考修复一致”不能单独证明质量正确。主分支/最终版的各次结果见[补充质量证据](data/final-2026-10-18/quality-probes.json)。

| 版本/运行 | float、Decimal 查询 | 日期边界长度/首项 |
| --- | ---: | ---: |
| 任务原版 | 4/4 | 4/4 |
| 上游参考修复 | 0/4 | 0/4 |
| 裸跑 r1、r2（分别） | 0/4 | 4/4 |
| 主分支 CEW r1 | 4/4 | 0/4 |
| 主分支 CEW r2 | 0/4 | 4/4 |
| 最终版 r1、r2（分别） | 0/4 | 4/4 |

这些用例是在独立审查发现问题后补充的：v1 是 float/Decimal 的 4 个查询，v2 保留 v1 并增加日期上/下界的长度和首项 4 个查询。
对父版、参考版和三组两次的全部 6 份该任务产物统一执行 8 项检查；没有回填冻结测试、
重跑模型或改写原自动完成率。它是补充质量证据，不能推断所有潜在回退，也不能单独证明回退由 Fast Path 引起。

- 这些是已用于方案开发的 7 个公开代码库任务，测试对代理可见，未使用留出任务，容易出现完成率天花板。
- 每题仅 2 次，未做显著性检验；并发、服务端状态和缓存都会影响耗时。数字只说明本轮观察结果。
- 现有目标和完整套件没有覆盖所有潜在缺陷；部分运行缺少静态检查工具，多版本 Python、Claude Code 宿主和生产环境未验收。
- 判分器的虚报检测是措辞启发式；补丁与终稿仍需要人工/独立审查。
- 本报告不使用之前试验的完成率或性能数字支持最终版结论。
