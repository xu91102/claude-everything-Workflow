## 剩余问题为何漏检

上一轮优化版的第二份 numeric_range 补丁读过 testing.md 和 code-review，也通过原有测试及八项已知边界检查。
它假设浮点除法与生成公式的偏差只影响少量位置：长度逐项增减，索引仅查商附近三个位置。
大偏移、小步长会让校正距离极大；浮点舍入还会产生重复值，使附近的匹配不是接口要求的首个匹配。

此前诊断已对原始两份产物只读复现：第一份大输入长度检查 43 ms、首个索引 11；第二份超过 2 秒、返回 18（实际 11）。
这排除了未加载规则和原始回归未通过的解释；验证样本与工作量分析存在缺口。
控制程序、源哈希和命令轨迹见[原因证据](data/quality-final-2026-10-19/quality-diagnosis.json)。原始产物未修改。

工作流规则相对本次修正前的 PR，只调整三处现有文件，AGENTS.md 不变。rules/common/testing.md 仍是三句有条件的验证约束：

- 并列验证已支持类型的上下限与新增中间运算、完整选择语义、终止和最坏工作量。

skills/code-review/SKILL.md 明确涉及多种算术类型或可配置算术上下文的数值搜索/校正重写须独立审查，并使用新上下文（fork_turns=none 或宿主等价机制），仅传固定审查包。保留低风险自审及必要独立审查，不降低模型或质量要求。

Fast Path 在现有读取步骤合并独立的 Git 状态、文件定位及已确定必要的规则片段；有先后依赖的步骤仍顺序执行。此前实际轨迹中存在分开的定位和状态请求，这项调整减少可避免的模型往返，不删除质量检查。

失败轮的阶段归因和本轮整体对照均是观察结果，没有对单条规则做因果消融；原生子代理及其用量单独保留供审计。

Fast Path 路由、按风险选择检查、片段读取和避免重复验证继续保留；没有任务名、数值、答案或新审批流程进入规则。
