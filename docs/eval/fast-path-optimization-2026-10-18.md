# PR #62 Fast Path 原因定位与同批复测

2026-10-18。7 个任务 × 2 次 × 3 组，**42 次实际 Codex 运行**，不补跑失败任务、不挑较优重复。
本轮直接比较 main、上一版 PR 和优化版；上一轮裸跑对照保留在[历史报告](final-benchmark-2026-10-18.md)，不混入本轮统计。

优化版相对上一版 PR：输入加输出 token **−16.7%**，平均 Agent 耗时 **−6.1%**。
相对 main：token **−28.0%**，耗时 **−10.0%**。
**质量仍未达标：优化版通过全部已执行检查 13/14。** 第二份 numeric_range 补丁在大输入长度检查中超过 2 秒，并将重复值的首个索引返回为 18（实际为 11）。
因此不能认定“提速且无质量回退”。main 和上一版通过全部已执行检查均为 12/14；这只描述本批产物。

AGENTS.md 与 main 逐字一致，净新增 **0 行**；PR 保持 Draft，不合并、不发布。

## 上一轮为什么更慢、更费 token

复核上一轮全部 42 次 CLI 输出及原始会话计量记录，得到三项直接证据：

1. main 到上一版 PR 的模型请求由 **122 次增至 128 次**；总输入由 4,054,789 增至 4,227,789。
   平均每次请求输入从 33,236 降到 33,030，约 −0.6%；请求数约 +4.9%。因此“少读了文件”没有转化成较低的累计输入。
   请求数从逐响应 token_usage_record 计数并与 CLI 总量逐次核对，不能拿 shell 命令数当模型轮数。
2. numeric_range 两次合计比 main 多 **130.7 秒**，占全部额外 153.2 秒的 **85.3%**；
   去掉该题后其余任务的总耗时差为 +2.6%。一次修复在语义检查完成后又安装 Ruff/Mypy/Flit/Twine 并构建、打包检查，
   从该阶段首次请求到退出共 **67.3 秒、358,386 输入 token**。这是阶段实测，不是这些工具的独立因果收益或可保证回收额。
3. 质量缺口不在风格或打包：局部成员查询新增对总长度的依赖，使有限浮点大范围、低精度 Decimal 的原有查询抛异常；
   一些长度校正还计算了日期边界之外的值。三组每组均有 2 份产物回退，所以上轮“全套测试绿”不支持质量保持结论。

原始轨迹、逐次计量与分类口径见[原因证据](data/optimized-2026-10-18/prior-diagnosis.json)。
这些轨迹支持优化方向，但上一轮只含 7 题、各 2 次；不能将小幅均值差全部归因于规则文本。

## 本次最小调整

- 在现有路由明确区分“修复公开函数既有行为”和“改变公共契约”，升级时只补缺失步骤。
- Fast Path 定位到函数和断言后只读必要片段；最终模块检查覆盖目标时不再重复跑目标检查。
- 由 testing.md 统一选择适用检查，保留用户和项目要求、风险与受影响依赖决定的质量门；工具或打包配置存在不自动构成发布检查要求。
- 增加补丁特有的兼容检查：新增局部到全局的依赖、原有合法输入的结果/异常/成本、值域/精度和已支持类型的边界。
  没有把具体任务名、数值或答案写进规则。

## 单独检查质量

在任何模型任务开始前，已冻结上一轮发现的 **8 个边界查询**。同样检查父版、参考修复和三组各两份 numeric_range 产物；
不修改任务夹具、不将检查细节加入模型提示、不事后挑选检查。完整原有套件仍按原判分器执行。

上游参考修复自身也未保留这些边界，所以质量依据是任务父版的既有合法行为，不能只看“像参考答案”。
已知边界未发现回退与独立补丁审查的结论应分别报告。

覆盖审计发现 main 的 humanize-346 r1 编译了翻译资源，使最终完整套件中 110 个原有跳过转为实际执行，总用例数没有改变。
因此另加一轮统一覆盖检查：所有计时结束后，复制 **12 份 humanize 产物**，编译相同资源，再用相同原始 venv 运行既有 i18n 测试。
这项补充是在观察到覆盖差异后加入的，独立列出，未改写原始耗时或评分，也没有补跑模型；它不能称为全部实验前预注册。
结果和控制脚本见[统一翻译覆盖检查](data/optimized-2026-10-18/i18n-probes.json)。

在优化版第二份 numeric_range 补丁的静态复核中又发现了按修正距离增长的循环，以及只检查商附近位置的索引实现。
因此对父版、参考修复、所有六份 numeric_range 产物统一增加两项补充检查：

- 大范围 `(1e16, 1e16 + 4, 1e-12)` 的长度应能在 2 秒内返回，并满足生成公式在最后一项/第一项边界之外的关系。
- 有重复浮点产值的 `(1e16, 1e16 + 4, 0.1)`，索引应等于实际有限迭代列表的首次匹配位置。

- 每次独立 checkout、HOME、Codex 状态、私有 venv；正式安装各冻结源码，AGENTS 三组相同。
  两个任务块并发，同题各臂串行轮换，第二次重复反转。顺序位置并非完全均衡，服务端负载和缓存不能强制清空。

  给定测试恢复后再判分；收集错误、中断、缺失/损坏/过期报告和全跳过均不算完成。
  原判分中的全套指固定的 pytest 套件；项目额外的 unittest/doctest、类型、构建和发布检查另见命令轨迹，不能统称已全部验收。
