3. 改进方案

P0-1Fast Path + 停止条件（已实施）

已写入 AGENTS.md 常驻策略（+1.9KB）：任务分级表、Fast Path 四步、升级条件、增量升级、命令预算。

## 任务分级与停止条件
| 微改 | 单仓库；改动 ≤2 文件；已有可运行测试；不碰公共 API/鉴权/迁移/不可逆副作用 | Fast Path |
| 常规 | 上述任一不满足 | 按规则索引读取相关规则 |
| 高风险 | 公共契约、鉴权、数据迁移 | 常规 + 09 对抗测试，必要时 Spec |

### Fast Path
1. 只读相关源码与测试，定位后直接修改；不先写 Spec/ticket/总结文档
2. 只跑目标测试；通过后跑受影响模块。不跑全量回归，不重跑已通过的检查
3. 不读 skills/、不读 rules/，除非命中升级条件
4. 完成时只说：改了什么、跑了什么、结果、剩余风险

### 升级条件
同一失败 2 次 / 改动面 >2 文件或改公共 API / 没有可运行测试 / 鉴权、迁移、不可逆副作用

### 升级是增量的
只读一份相关规则或技能；构建、全量回归、E2E 只在提交或发布时跑；兼容性类型放宽不算高风险

### 命令预算
微改：探索 ≤4 条（不含依赖安装），验证 ≤3 条；超出前先说明理由

同时改了 skills/using-superpowers/SKILL.md：新增 Micro Task Fast Path 段，并收紧两条路由：

- reported bug or unexplained/repeated failure? -> systematic-debugging
+ unexplained failure, or same failure twice?    -> systematic-debugging

- behavior change with a test path? -> TDD
+ behavior change without clear acceptance, or needs new tests?
+                                                -> TDD

实测：命令数 9.6 → 6.9（原 CEW 18.9），输入 token 243k → 186k； 完成率 14/14，未读技能 7/7。预期值（≤11 条命令、≤ +10% token）被超额完成， 但幅度受单次噪声限制，见第 0 节的说明。

P0-2验证白名单：禁止“顺手全跑”（已实施）

当前 CEW 在 1 行修复上跑了 doctest、benchmark、ruff、black、翻译脚本和全量测试。已在 rules/common/testing.md 增加按改动面选择的白名单：

改动面必跑不跑
单个纯函数 / 工具函数该文件对应的测试文件全量套件、E2E、构建
单个模块内部实现该模块的测试目录其他模块、E2E

公共 API / 依赖升级 / 发布全量测试 + 构建—

并补四条硬约束：同一结论只验证一次；lint 只在提交/完成前跑一次；依赖安装每任务最多一次； 验证命令超过 3 条要先说明理由。

实测：定向测试比例 8/14 → 11/14（裸跑 → 新 CEW），没有出现“少跑测试换速度”。

5. 风险与回退

  • 提示词门禁不硬。模型可能仍然多跑。先测遵从率；低于 90% 就改用独立 cew-fast profile（精简 AGENTS + 精简技能），而不是继续加规则。
  • 停止条件可能伤到困难任务。用“失败 2 次”做硬触发器，并在困难集上验证；不达标就不默认开启。
  • 技能发现性下降。extended 技能不在扫描目录，必须靠 INDEX + 路由显式路径；加检索测试。
  • 插件安装路径未覆盖。本次改动作用于 npm installer；plugin marketplace 仍装全量技能，需要另行分层或文档说明。
  • 宿主差异。Codex 与 Claude Code 的技能发现机制不同；先在一侧达标，再复制到另一侧。
