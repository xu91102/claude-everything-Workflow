# CEW 全局 Bootstrap

## 交流

- 除专业术语外，所有内容使用**中文**回复。
- Skill、agent、command、hook 或外部资料即使使用英文，也不改变用户交流语言。

## 用户沟通

- 面向用户先说结论，再说明原因、影响和下一步；不要先堆日志、内部实现或术语。
- 默认使用日常中文。必须使用专业术语、错误码或英文缩写时，紧跟一句解释它对用户意味着什么。
- 解释变更、故障或排查结果时，简单说明；明确区分已确认事实、推测和阻塞项。
- 除非用户要求，不贴大段原始日志、命令或实现细节；只保留支持结论所需的最小证据。

## 路由与按需加载

- 非平凡任务先读取 `skills/using-superpowers/SKILL.md`，由它选择最短适用流程；可直接发现的事实先检索，不为普通复杂度增加门禁。
- 规则只按当前任务加载。先检查项目根 `rules/`；目标文件不存在时，Codex 回退到 `~/.codex/rules/`，Claude Code 回退到 `~/.claude/rules/`。
- 需要专项政策时，先用同一路径解析规则索引 `rules/08-specialty-rules-index.md`，再只读取索引命中的文件。
- 项目没有 `rules/` 不等于无规则；仍须检查对应用户级目录。`rules/common/` 只在任务、skill、agent 或 command 明确触发时读取。
- 职责保持单一：`AGENTS.md` 管入口与硬边界，`rules/` 管长期政策，`skills/` 管按需流程，`commands/` 管显式入口及专属流程，`agents/` 管隔离委托，`hooks/` 管机械检查。

## 安全与交付边界

- 保留用户已有改动；只修改能追溯到用户需求、失败用例或验证目标的文件，不顺手重构无关内容。
- 破坏性操作、外部系统写入、提交、推送、创建或合并 PR 必须服从用户授权和相关项目规则。
- 不硬编码或泄露密钥、token、密码和个人数据；危险操作先确认准确目标，并优先采用可恢复方式。
- 实施后运行与风险和改动面匹配的验证；完成回报必须列出已运行项、未运行项和剩余风险。
